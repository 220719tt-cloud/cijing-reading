# 独立中文分节编号：对齐校验失败修复

2026-10-18。仅前端修复，不修改或部署 Worker，不推送或部署网站。

## 原因

在阅读器临时切换0%原文后，按两个实际UTF-16源范围核对：10344–10354和11005–11015分别是空行包围的独立`（七）`和`（八）`。它们是书内分节编号，并非漏译的叙述句。

原先中立内容判断只接受Unicode数字、标点和空白，汉字`七`、`八`属于字母类别，因此被送去AI。而严格英文校验要求译文包含拉丁字母，只有Unicode数字/标点且与原文一致才例外。数字形式`（7）`会被拒绝，原样中文编号也会被拒绝，最终统一归类`MODEL_ALIGNMENT_INVALID`。该错误还涵盖错ID等问题；Worker没有返回原始模型文本，本轮没有读取云端私密日志，不能声称知道这两次原始输出的确切内容。但已确定这两处不应作为自然语言正文交给模型翻译。

## 修复边界

- 新增通用、本地的独立中文分节编号识别与转换；不含当前书名、坐标或缓存ID特判。TXT与EPUB均走同一引擎。
- 仅接受完整括号包围、独立成行的中文数字：如`（七）`、`(十一)`、`【两百零三】`、`[一千零一十]`，经数值解析和规范中文数字回写核对，再转为相同值的阿拉伯数字。保留外层括号、空白、换行和原文锚点。范围0–9999，无法确定的保留原流程，不猜测。
- 拒绝`七岁`、姓名、`（七个孩子）`、句中房号、`十十`、`一百二`等正文或模糊数词。正文、ID、中文残留、结构与术语校验不放宽，Worker协议与安全措施不变。
- IndexedDB仅允许上述确定的精确数值转换作为新中立例外；错数字、任意中文或额外内容不能借此通过。已有正常英译编号继续可用。
- 显式重试沿用原有缺口队列，仅补这两个失败范围，逐个事务保存并清除对应失败记录。不重发或替换已经成功的437个句组。这里不需要额外云请求。
- 独立编号不计为英文正文覆盖率；缓存完成度仍包括其处理状态。0%保留原文，非零档显示已缓存编号的对应形式，不伪造英文句子或学习词条。
