# 自动翻译：一次处理，失败跳过

2026-10-19。本标准取代旧格式恢复文档中的自动重试／失败后拆批策略。未清空、迁移或升级用户数据库；没有部署 Worker 或阅读网站。

## 当前前端行为

1. 每次任务先读取 IndexedDB，按不可变的原文范围扣除成功缓存，再排除已有跳过记录。普通自动任务不重发任何成功或已跳过的范围；只有用户主动点击「重试翻译本章」才包括旧失败范围。
2. 排序后的队列只消费一次。普通叙述最多3句组／450字符；完整对话、长句和主动补翻的失败范围在首次请求前单独编组，复用线上 Worker 已有单句纯译文路径。编组发生在请求前，不是失败后拆分重发。
3. 普通模型错误每批最多一次 HTTP 请求。模型 JSON、输出、对齐、术语错误及普通502／504直接记录源范围、固定错误码、尝试次数和时间，保留中文并继续下一批。明确网络中断／客户端超时例外，使用有限恢复机制，见 [网络恢复](TRANSLATION-NETWORK-RECOVERY.md)；不把未处理文本标成跳过，不拆分格式错误重发。
4. 收到完整合法 JSON 时，仅接受请求中明确、唯一的 ID。逐项独立校验英文内容、长度、术语和人物拼写；重复 ID 的所有同名项均不采用，未知 ID 不映射到正文。已通过项先提交 IndexedDB，再持久保存其余跳过项。坏 JSON 不做子串提取、正则修补、顺序猜测或英文占位填充。
5. 成功子集提交后，随后写跳过记录失败不会回滚先前成功内容。数据库读写异常、并发写冲突明确停止，不能假装保存成功；原文／已有缓存保留。
6. 403、429、503、取消、存储故障仍安全暂停；网络故障仅允许每轮共享最多3次无AI探测及2次额外翻译重试，无法恢复则暂停。429保留冷却期；全部翻译请求（含重试）仍经过6.1秒调度并计入单轮240次上限，达到上限时保留待翻译队列，不把未请求范围记为跳过。
7. 全队列耗尽后状态为「本章自动处理结束」，与「完整译文缓存」区分。显示成功缓存、已跳过、待处理、处理进度及按对应原文内容计算的译文覆盖率，包含此前缓存。处理100%不等于译文100%；成功+跳过覆盖全章才是本次处理结束。
8. 0／20／40／60／80／100原有混排和进度锚点保留。未翻范围仍为中文；100%档缺少完整译文时沿用既有明确提示，不伪装为完整英文。

## 与当前线上 Worker 的边界

无需部署 Worker 即可使用前端「错误直接跳过、继续后文」机制。现有线上版本对坏批次是整批拒绝：只返回错误码／原因，不返回模型中的有效项目。因此前端不能回收服务端没有交付的译文，也不能把502当作已有部分翻译成功。

本地另外准备了 `worker/translation.ts`、`worker/modelOutput.ts` 及生成的完整 `worker/worker.js` 修订：在同一次 AI 调用后，仅对完整 JSON 内明确对应的项目逐项严格校验，返回成功子集。没有额外推理、不修坏JSON、不接受截断输出、没有取消来源限制／限流／开关；接口仍为 version:1、segments、context、glossary。前端可识别成功子集并标记遗漏项跳过。

**该 Worker 修订尚未部署，必须先得到用户正式发布确认。** 本地替身证明的是控制流和结构安全，不是新 Worker 已在云端运行，也不能证明文学译文准确。首次实际翻译成功率取决于模型，80%是期望，不通过重试凑覆盖率。

发布顺序须协调：虽然 JSON 字段没有改变，但旧版公开前端要求整批完整，不能消费新的成功子集。应先发布支持子集的新前端，再按用户确认更新 Worker；不能只更新 Worker 后让旧公开前端反复拒绝局部成功结果。本轮只在本地验证，不替用户执行其中任何发布。

## 自动测试

- 一次处理成功／跳过混合章，所有首次待译范围只进入一次请求，后文继续、进度结束且原缓存逐字段不变。
- 完整JSON中乱序有效项保存，重复ID／错ID／中文／人物错译／无效术语拒绝；坏JSON和截断不抢救。

- 连续45个失败仍处理最后3个正常句组；无自动重发、无12次恢复停章。

## 本轮本地和真实结果

最终216项自动测试、TypeScript检查、生产构建、根路径及Pages子路径静态检查通过。没有提交／推送／部署。

沿用用户原有当前 EPUB 阅读分节，起点172成功、8旧失败、146未处理。新任务默认跳过旧失败；完整对话首次单独请求，叙述按原小批次请求。最终 **259成功缓存、67跳过、0待处理，界面显示译文覆盖约80%，处理进度100%**。跳过中包含8个旧失败和59个本轮未确认范围。本轮任务界面统计76次调用；无点击手动补翻，也没有为追覆盖率重试跳过范围。
