## 问题及前端修复

- 失败源范围多数为8–65字的完整短对话，已逐句组请求，不是只靠继续减小批次就能解决的大文本问题。JSON生成、ID抄写和术语表生成仍然给每条单句增加了格式负担。
- 上下文原先固定重复章节开头/简介，邻近内容反而可能被截断。现在只使用目标前后就近上下文；只发送需要翻译的范围作为`segments`，不重复把目标文本当上下文。正常范围约900字符内，恢复约400字符，已有必要的人名拼写仍附带。
- 多句失败继续按完整句组拆批到单句，不在对话中任意切字符或猜测句子对应。单句的JSON错误/对齐拒绝至多额外重试一次，改为紧凑上下文；输出截断等问题不重复明显失败的大批次。
- 本地转发原先会将上游HTTP200但无效JSON/不对应的响应变成无错误码502，阻止恢复；现在返回固定`MODEL_JSON_INVALID`/`MODEL_ALIGNMENT_INVALID`/`MODEL_OUTPUT_INVALID`分类。网络、429、503等仍停止而不是当模型格式错误无限重试。
- 沿用3句组/450字符、6.1秒间隔、每轮12次额外恢复调用和总预算；原有成功源范围不进入新请求，每个成功子批立即事务保存。恢复不会清空缓存。

## Worker内部修复（代码已准备，云端未更新）

文件`worker/translation.ts`、`worker/modelOutput.ts`，单文件产物**`worker/worker.js`**。

1. 对**一个完整句组**，让模型只生成实际英文，不再要求它把对话引号/反斜杠嵌入JSON、抄ID和重写术语表。代码以唯一请求ID封装返回JSON；`JSON.stringify`负责正确转义。这里没有根据多句返回顺序猜测映射，也没有填入固定英文。
2. 多句仍走严格JSON和完整ID集合校验。单句若模型依然返回完整JSON，也仅在它完全通过原校验时接受；坏JSON不正则修补，不从半截结果抢救英文。
3. 拒绝结束原因显示截断、超大或空输出、未闭合思考、混入说明/代码、未闭合英文弯引号、中文冒充英文、错ID和不合法术语；原文中已有固定人名若在单句译文中丢失/变拼写也拒绝。只返回固定诊断`reason`，不泄漏模型原文、私人小说或异常堆栈。
4. 单句保留已有术语表，不要求模型额外输出名称JSON；多句仍可严格增加新名字。单句中新名字依赖上下文及模型推断，不凭空自动构造其拼写表，也不增加第二次AI调用来抽取人名。
5. 一个HTTP请求最多一次`env.AI.run`，没有隐式额外模型重试。温度0.1；单句按输入长度设置1024–8192输出tokens上限，多句3072。没有增加免费额度、关闭限流或改用其他服务。
6. 外部仍是相同`POST /translate`、`version:1,segments,context,glossary`，返回`version,model,translations,glossary`。保留`AI`、`PER_IP`、`GLOBAL`及现有开关和来源校验；不改绑定/来源名单/限流配置。不需要前端密钥。

当前Qwen模型未列入Cloudflare官方JSON Mode支持列表，因此没有盲目添加`response_format`或宣称严格JSON模式可用。官方依据：[模型参数](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/)、[JSON Mode支持列表](https://developers.cloudflare.com/workers-ai/features/json-mode/)。
