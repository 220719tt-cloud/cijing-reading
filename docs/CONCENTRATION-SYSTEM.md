# 六档英语浓度：统一原文覆盖预算

更新：2026-10-17。本次为现有阅读器增量重构，不变更 Worker 接口、模型、CORS、限流、数据库版本或部署。旧文档内“20% 只本地、40% 整句约20%、60% 才启动云翻译”的描述是历史行为，以本页为准。

## 根因与修复

1. 原20%直接返回本地显示，忽略已经下载的章译文；自动翻译触发及授权控件也仅在60%以上出现。现在任何非零档位都可在原有授权后启动当前章翻译，所有档位共用一份 IndexedDB 译文。
2. 原40%整句实际目标20%、硬上限35%，随后叠加稀疏词语。现在六档共同使用原文范围预算，没有这些特殊上限。
3. 原本地句型在双语组合之后另外叠加，统计没有包含它们。现在先汇总经过筛选的本地词组/句型，再与真实译文一起规划，只组合一次。
4. 原各档独立做子集选择，60/80并不保证包含20/40英文范围。现在从20逐级增加到80：优先保留已经选中的整句；局部词组可以被覆盖它的完整译句升级。普通细句章节保持英文原文范围包含关系，粗句组确实无法同时满足时优先接近目标并明确解释。100%使用所有已缓存的正文译文，尚未翻译或跳过的范围保留中文；不需要等待整章完整。
5. 原实际百分比只统计缓存整句。现在按最终显示模型中所有英文编辑的原文范围并集计算，词组/句型/AI句组只计一次；查词拆分重复的原文范围也不重计。
6. 原已暂停/失败后可能隐藏已有进度。现在已有部分缓存也显示实际缓存进度。

## 指标和算法

- 分母：当前章节正文中的 Unicode 字母（包括汉字）数量。空格、标点、数字、图片、EPUB heading/pre 块属于语言中立结构，不虚增英语比例。以原文位置计数，不以英文译文长度或模型调用次数计数。0%表示原文，英文原书不反向翻译成中文。
- 分子：当前显示为英文的对应原文范围内，上述正文单位的去重数量。界面显示一位小数，真实验收另记录分子/分母。
- 分段仍由原有翻译引擎按完整句组切分（保留引语及说话标签），没有重新发明译文接口或猜测中英词级对齐。
- 相同章节、缓存和设置产生相同输出。稳定哈希只作相同预算下的优先级，绝不将命中概率当作浓度。
- 20/40在共同预算中保留少量经过语境筛选的词组及精确句型；整句供应主要覆盖。60/80继续扩大完整译句，不拆开英文、不会从译句中截取片段硬拼中文。
- 低档初始本地表达预算最多约4%正文（不足不补造），随后用完整译句填充至20%；40再扩展。同一目标不足的零碎空间可由安全本地表达补齐。句内词组与完整译句互斥，跨译文范围的本地表达被跳过。
- 位集子集选择器选择最接近预算的剩余完整句组。只处理当前章，长书不全部渲染；没有新增大型词库、模型或第三方依赖。
- 短章或人工导入的超长句组，可能无法同时满足“逐档嵌套、完整句子、精确20%步长”。保留完整句组优先；若严格嵌套导致超过2个百分点的偏差，会比较能否调整少量整句更接近目标，优先保留之前范围、保持总覆盖不下降，并在面板明确解释。仍无法精确达到时显示实际偏差，不截句、不伪造数字。

## 缺失、失败与缓存

- 首次非零档仍需要现有明确云翻译授权；未授权时本地表达不足就显示真实比例。不会为了达标随意反转词典。
- 所有非零档复用原先`version:1 / segments / context / glossary`协议、分批限制和原生 IndexedDB。切换非零档不取消重开同一任务；回0%停止未完成请求，之后只补缺少部分。
- 当前英文覆盖率和翻译缓存进度是两个指标。缓存进度沿用已有非空白原文完整性校验，不将中立结构的完成状态混成英文比例。
- 缺失/失败时仅显示已有安全范围，其他保留中文；界面状态显示失败、暂停或继续入口。100%显示全部已确认的缓存正文译文，保留缺口中文并显示实际英文覆盖率；缓存完整状态保持真实，不把“目标100%”伪装为“实际100%”。
- 仍使用原文UTF-16位置保存阅读锚点。字号变化可使用原有显示指纹辅助，换浓度后回到原文锚点；原书、书库、收藏与掌握数据没有迁移或清空。

### 真实译文质量边界（必须保留）

本次修复保证的是“范围完整、预算真实、稳定混排”，并不证明现有AI模型的文学翻译已经合格。抽查发现原作的古白话和指代仍会误译，例如“怪他多事”指车夫却出现`annoyed at her`，以及“我摔坏了”输出`I'm broken`不够地道，另有“皮袍下面藏着的『小』”的指代不准确。本次没有偷偷改写缓存、注入固定英文或声称这些错误已经修好。若要承诺整章译文在人物关系、文学隐喻上可靠，还需要独立的模型翻译质量评估和后续修正方案；未为本次改变已正常工作的Worker。
