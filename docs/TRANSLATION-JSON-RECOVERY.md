# MODEL_JSON_INVALID：前端恢复与真实验收

更新：2026-10-18。沿用已部署的 Cloudflare Worker `/translate`，没有修改或部署 Worker，没有推送或部署阅读网站。

## 已确认的问题与未确认的模型细节

- 报错来源是 Worker 的模型输出解析阶段。它已经收到请求并生成过一部分有效译文，因此该次`MODEL_JSON_INVALID`不是CORS来源403或本地书库丢失。
- Worker对原始模型文本执行`JSON.parse`；已有提示要求仅JSON、正确转义对话引号、ID一致，并去除完整的前置think块/代码围栏。但系统提示词不能保证自由生成的文本一定合法。
- `MODEL_OUTPUT_INVALID`能识别有明确`finish_reason=length`的截断、空响应或过大响应；只有`response`字符串却没有结束原因时，截断也可能落到`MODEL_JSON_INVALID`。额外说明文字、未转义引号/换行、反斜杠或不完整JSON也可能属于该错误。**现有云端错误响应不含原始模型文本，本轮没有读取云端私密日志，不能断言这一次究竟是哪一种字符错误。**
- 旧前端每批最多8句组/900字，JSON错误只重试一次且共享65秒时限；再失败就终止整章，不拆批，不记录逐句失败。已成功的旧批次确实保存了，但失败批次后面的内容没有机会继续。
- 旧请求还会带整章已累积的最多60个人名，即使它们没有出现在当前批次/上下文中。Worker提供的输出模板又包含这份术语表；这可能无谓扩大模型输入/输出JSON，而不是已证实的这次具体失败原因。

## 本次修复

1. 默认每批**最多3个完整句组、450个原文UTF-16单元**。超过450但不超过原服务3000上限的完整单句独立发出，不机械截断英文或拆碎对话来凑长度；更长的句子记录`SOURCE_TOO_LONG`并保留中文，后续内容继续处理。
2. 单次HTTP传输只发一次，不在底层暗中重试。引擎统一计数：`MODEL_JSON_INVALID`同尺寸最多2次，仍失败按原句组ID二分（3→2+1，2→1+1）。输出截断/对应/术语错误直接拆小，不重复明显失败的大批次。每个单句仍失败时独立记录，继续其他句组。
3. 每个成功子批次立即严格校验完整ID集、英文内容、术语与原文范围，然后事务写入IndexedDB；不会等整个父批成功才保存，也不从坏JSON中抢救不确定的部分英文。
4. 失败只存固定错误码、原文范围、直接尝试次数和时间，不存原始模型响应、不记录私人小说应用日志。旧`cijing-translations` v1增加可选元数据，不升级/清空任何数据库。
5. 再次打开默认跳过已记录的顽固失败，不循环耗额度；「重试翻译本章」明确允许重试失败及未完成范围。「继续翻译本章」复用成功缓存；有失败且还有其他待处理范围时可选择「跳过失败句组，继续其余内容」。成功补齐后清除对应失败记录。
6. UI分开显示成功缓存/失败或暂未完成/待处理句组数、缓存百分比、当前显示英文比例、本次实际调用次数和上限。错误列表可查看每个范围、固定原因及尝试次数；部分失败不再被标为整章完成。
7. 相同服务在标签页内串行安排调用开始时间，至少间隔**6.1秒**，包括重试/子批；下一可用时刻保存在localStorage以延续刷新冷却。与其他标签页/不同设备共享IP的竞争仍由Worker最终限流。429停止自动恢复，尊重可读取的`Retry-After`且冷却至少60秒；403/503/网络/超时/存储失败不递归放大调用。
8. 每轮最多12次额外恢复调用，并有按剩余内容计算的请求上限（至少24，绝不超过240）；到达预算会保存成功部分、记录尚未完成范围并明确停止，读者决定继续或重试。此为调用上限，不是对账户实际Neurons账单的精确计量。
9. 只发送当前批次及必要上下文实际出现的人名；所有有关人名保留缓存的固定拼写，完整术语表继续留在本地，不把无关人名反复塞进每次JSON。原接口仍是`version:1, segments, context, glossary`。
10. HTTP请求使用短ID `s0`、`s1`、`s2`，降低模型抄写长数字ID的负担；严格核对返回ID全集后，才映射回原有不可变的原文范围与缓存ID。显式重试优先处理已有失败，且已知失败句组单独请求，不把它重新混入正常大批次。

## 为什么本轮不需要更新Worker

Worker已有输出上限（普通批次3072 tokens，超长独立句8192）及安全提示词。前端通过更小输入与精简无关术语来减少达到输出上限的风险，不能、也没有在请求中偷偷覆盖系统提示词或`max_tokens`。目前真实连续测试已通过，先保留同一后端便于确认前端改善，CORS/AI/PER_IP/GLOBAL/限流全部保持。

当前真实测试仍发现单句对应校验失败，因此前端恢复不能保证每个范围最终都成功。如果后续需要继续改进后端，应另行审核结构化输出支持与仅含输出长度/结束原因的安全诊断，而不是用正则补造坏JSON。当前Qwen3模型不在Cloudflare官方JSON Mode支持列表内，不能仅因通用模型参数列出了`response_format`就假设可用。本轮没有更换模型、实施或部署后端变更。依据：[官方模型说明](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/)、[JSON Mode支持列表](https://developers.cloudflare.com/workers-ai/features/json-mode/)。

## 验证：模拟与云端分开

**故障注入自动测试**：模拟连续无效JSON、输出截断、错ID、顽固单句、预算耗尽、429/503/超时、空间不足、取消、刷新及React缓存重读，检查有限调用、逐子批落库、失败记录往返、只补缺口、术语筛选和原文对应。故障替身不作为真实AI质量证据。

**真实云端整章**：通过现有网页和已授权的仅本机开发转发，调用实际部署的`https://cijing-translation.220719tt.workers.dev/translate`。新来源没有预置译文，将鲁迅《一件小事》全文导入后在60%档启动：**13次真实请求，37个句组，缓存100%，失败0、待处理0，实际显示英文约60%**。没有手工填入英文，也没有改Worker。此篇测试没有模型格式错误。

**用户原章续传与真实故障恢复**：保留原有32句组/6%缓存、阅读位置及词汇记录，原位重新读取后继续。最终已缓存**198个句组/47%**，实际显示英文**48.9%**，失败1个、待处理240个；验收后已暂停以限制继续消耗额度。最后一轮10次调用中，模型输出异常6次，最近为`MODEL_JSON_INVALID`，引擎自动恢复后仍新增了成功缓存，未因坏批次终止后续内容。剩余失败为第1段原文UTF-16范围10344–10354，`MODEL_ALIGNMENT_INVALID`，直接尝试累计2次；已记录并保留中文。这样真实验证了JSON异常后的续传，但不代表所有模型错误都能恢复。该长章尚未整章完成，不冒充100%验收。

结论：实测整章能够完成，原长章能够越过此前停滞继续积累有效缓存；不能保证任意模型输入永不失败。顽固单句保留中文、允许跳过并继续，但这类缺口未补齐前100%模式仍不假装整章英文。仅小批次会增加调用次数，速度受限流和免费额度影响。

本轮全量自动测试187项通过，并运行TypeScript检查、生产构建及静态托管检查。真实iPhone/Android仍待实机验收；本次采用通用Web API，没有新增模型/付费服务/依赖。
